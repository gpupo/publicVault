CQRS + Event Sourcing costuma se integrar melhor com aplicações modernas orientadas a dados e IA, mas MVC continua sendo mais simples e suficiente para muitos sistemas.
A diferença principal está em como os dados são registrados e distribuídos.
## Notas

IA funciona melhor com **sequências de eventos**.
Isso permite treinar modelos para:
- previsão de compra
- recomendação de produtos
- previsão de demanda
- detecção de fraude

### MVC (Model-View-Controller)
- Arquitetura clássica e predominante em aplicações web.
- Fluxo de execução: User -> Controller -> Model -> Database -> View.
- Conceito central: utiliza um único modelo para operações de leitura e escrita.
- Persistência: o banco de dados armazena apenas o estado atual do objeto (ex: uma tabela de pedidos com o status atual).
- Vantagens: simplicidade de implementação, modelo único e banco de dados único.
- Indicação: sistemas CRUD e aplicações de complexidade baixa a moderada.

### CQRS + Event Sourcing
- Arquitetura que separa as responsabilidades de escrita e leitura e registra a mutação de dados como uma série de eventos.
- Fluxo de execução: Command -> Domain -> Event Store -> Projections -> Read Models -> Query.
- Conceito central: a escrita é isolada da leitura e o estado é reconstruído através do histórico de eventos.
- Persistência: armazena-se a "história" do que aconteceu (ex: OrderCreated, ItemAdded, OrderPaid) em vez de apenas o estado final.
- Vantagens: auditoria nativa, alta escalabilidade e modelos otimizados para consultas específicas.
- Indicação: domínios complexos, sistemas que exigem rastreabilidade total (auditoria) e alta escala.



### Comparação Direta

| Característica | MVC Tradicional | CQRS + Event Sourcing |
| :--- | :--- | :--- |
| **Foco** | Organização da aplicação | Organização do domínio e histórico |
| **Estado** | Salva o estado atual | Salva a história (eventos) |
| **Modelos** | Modelo único (Shared Model) | Modelos de escrita e leitura separados |
| **Complexidade** | Baixa | Alta |
| **Componentes** | Controller, Model, View | Handlers, Projections, Event Store, Read Models |

### Considerações Arquiteturais
- O [[MVC]] foca na estrutura de interação do usuário com o sistema.
- O [[CQRS]] com Event Sourcing foca na integridade e na evolução dos dados no tempo.
- A transição do MVC para o CQRS geralmente ocorre quando a complexidade das regras de negócio ou a carga de leitura superam a capacidade de um modelo simplificado.
- Muitas empresas modernas (Uber, Netflix, Stripe) adotam arquiteturas **event-driven**, que conceitualmente se aproximam de CQRS + Event Sourcing porque **eventos são o combustível dos sistemas de dados e IA**.
