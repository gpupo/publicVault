`git worktree` permite que um único repositório tenha **múltiplas árvores de trabalho ativas ao mesmo tempo**, cada uma vinculada a uma branch diferente. Isso elimina a necessidade de `git stash` ou de trocas constantes de branch para alternar entre tarefas.

Cada **worktree** funciona como um **clone leve do repositório**: os diretórios de trabalho são independentes, mas todos compartilham o mesmo `.git` e os mesmos objetos internos. Cada diretório permanece fixado em uma branch específica.

Na prática, isso permite manter **uma branch por diretório** — por exemplo, `main`, `feature` e `hotfix` — trabalhando em paralelo sem alternar de branch continuamente. Além de simplificar o fluxo de desenvolvimento, evita efeitos colaterais comuns ao trocar de branch, como recompilações, reconstrução de cache ou reinicialização de ambientes da aplicação.

## 1. Preparação do Ambiente
Crie um repositório inicial para testes:

```bash
mkdir worktree-demo && cd worktree-demo
git init
echo "Hello main" > app.txt
git add .
git commit -m "initial commit"
git branch feature
````

## 2. O Conceito Central: Adicionando uma Worktree

Diferente do `git checkout`, que altera os arquivos no diretório atual, o `worktree add` cria um novo diretório físico para uma branch específica, compartilhando o mesmo histórico `.git`.

```bash
git worktree add ../feature-worktree feature
```

## 3. Trabalho em Paralelo (Simulação)

### No Diretório Principal (`main`)


```bash
cd worktree-demo
echo "main change" >> app.txt
git commit -am "update main"
```

### No Novo Diretório (`feature`)


```bash
cd ../feature-worktree
echo "feature change" >> app.txt
git commit -am "update feature"
```

## 4. Gestão e Visualização

Para verificar as árvores ativas e o gráfico de histórico:


```bash
# Listar diretórios vinculados
git worktree list

# Visualizar a divergência dos históricos
git log --oneline --graph --all
```

## 5. Modelo Mental e Sinergia com IA

O modelo mental substitui o fluxo linear (editar → stash → switch) por um modelo expansivo (múltiplos contextos físicos).

### Fluxo com IA e Agentes

Em fluxos modernos, é comum manter estruturas separadas para que ferramentas de IA operem sem interferir no código estável:

- `projeto-main/`: Código estável e produção.
    
- `projeto-ai-exp/`: Diretório para a IA testar refatorações ou gerar novas features.
    
- `projeto-hotfix/`: Correções urgentes que não podem esperar o término da feature atual.
