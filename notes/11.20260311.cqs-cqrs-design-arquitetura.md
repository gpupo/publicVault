## Notas

### CQS — Command Query Separation
- Princípio de design proposto por Bertrand Meyer.
- Regra fundamental: uma operação deve alterar o estado ou retornar dados, nunca ambos.
- Command: Operações que mudam o estado do sistema, executam regras de negócio e produzem efeitos colaterais. Não retornam dados relevantes. Exemplos: deposit(), cancel(), increaseStock().
- Query: Operações que apenas retornam informação, são idempotentes e não modificam o estado. Exemplos: getBalance(), findByCustomer(), getQuantity().
- Violação comum: O método pop() de uma fila, pois retorna o item e altera a fila simultaneamente. A solução aderente separa em peek() (query) e remove() (command).
- Benefícios: previsibilidade, menor acoplamento, testes simplificados e APIs mais claras.

### CQRS — Command Query Responsibility Segregation
- Padrão arquitetural introduzido por Greg Young que expande o CQS para o nível de sistema.
- Conceito central: o modelo de escrita (Write Side) é diferente do modelo de leitura (Read Side).
- Lado de Escrita (Command Side): focado em validações de domínio e regras de negócio. Fluxo: Command -> Command Handler -> Aggregate -> Persistência/Event Store.
- Lado de Leitura (Query Side): focado em consultas, relatórios e dashboards. Fluxo: Query -> Read Model -> Banco otimizado para leitura.
- Projections: processos que transformam eventos ou mudanças de domínio em modelos de leitura atualizados.
- Event Sourcing: arquitetura frequentemente combinada ao CQRS onde o estado é reconstruído a partir de uma sequência de eventos.

### Comparação e Aplicabilidade
- [[CQS]] é um princípio de design aplicado ao nível de método ou classe.
- [[CQRS]] é um padrão arquitetural aplicado ao nível de sistema, separando modelos física e estruturalmente.
- Vantagens do CQRS: escalabilidade independente de leitura/escrita, modelos especializados e consultas simplificadas (sem joins complexos).
- Desvantagens do CQRS: maior complexidade arquitetural e necessidade de lidar com consistência eventual.
- Indicação de uso: recomendados para domínios complexos, sistemas de alta leitura, microservices, ERPs e fintechs. Sistemas CRUD simples geralmente não necessitam de CQRS.
